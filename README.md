# Zandronum Server Watcher

A small always-on-top desktop overlay that shows live information about the Zandronum
servers you care about: who is playing, on which map, in which game mode, and how full
each server is.

![Overlay running over a game window](docs/overlay.png)

## Status

Early but working. The protocol layer is complete and tested against live servers; the
overlay renders real data and polls on an interval.

- ✅ Master-server listing (Huffman-coded, paginated)
- ✅ Per-server launcher query with player roster
- ✅ Always-on-top transparent overlay, click-through friendly, out of Alt+Tab
- ✅ 34 unit tests covering the codec and both response parsers
- ⬜ Tray icon and settings UI
- ⬜ Auto-discovery of servers from the master list

## Requirements

- Windows 10 or 11
- .NET 10 SDK (pinned in `global.json`)

## Build and run

```powershell
dotnet build
dotnet run --project src/ZandronumWatcher.App
```

Run the tests:

```powershell
dotnet test
```

Publish a standalone build:

```powershell
dotnet publish src/ZandronumWatcher.App -c Release -r win-x64 --self-contained false
```

## Configuration

Watched servers live in `servers.json` next to the executable:

```json
{
  "pollSeconds": 15,
  "servers": [
    "78.36.200.207:10666",
    "78.82.95.98:10666"
  ]
}
```

## Why the protocol layer looks the way it does

A few details are easy to get wrong, and each one is handled explicitly:

**All traffic is Huffman coded.** Both master and game servers expect Doom's Huffman
codec, not plain UDP payloads. The first byte is the padding-bit count, bits are packed
LSB-first, and a leading `0xFF` marks a raw (already-compressed) payload. See
`Huffman.cs`; the 256-entry table is generated by `tools/generate-huffman-tables.py`.

**Servers rate-limit repeat queries.** Zandronum ignores queries that arrive within
roughly 10–12 seconds of the previous one (`sv_queryignoretime`), answering with
`MSC_REQUESTIGNORED` instead of data. The default poll interval is therefore 15 s, and
the UI keeps showing the last known state rather than blanking out.

**Dead servers are normal.** Around half of the entries advertised by the master server
do not answer at all. Queries use a 2 s timeout and are bounded by a concurrency
semaphore, so one dead host cannot stall the refresh.

**Resolve by name, not by IP.** Proxy setups such as Mihomo TUN hand out fake-IP
addresses in `198.18.0.0/15`; connecting to a hard-coded literal IP bypasses the proxy
and fails. `ZandronumClient` always resolves the hostname first.

## Project layout

```
src/
  ZandronumWatcher.Core/     protocol + polling, net10.0, no UI dependencies
    Protocol/                Huffman codec, packet reader, response parsers
    Models/                  ServerInfo, PlayerInfo, ServerEndpoint, ...
    Services/                ZandronumClient, ServerWatcher
  ZandronumWatcher.App/      WPF overlay, net10.0-windows
tests/
  ZandronumWatcher.Core.Tests/   xUnit, includes reference vectors from pyzandro
tools/
  generate-huffman-tables.py     regenerates Protocol/HuffmanTables.g.cs
```

`Core` deliberately targets plain `net10.0` so the protocol logic can be tested on any
platform. Only the overlay project is Windows-specific.
